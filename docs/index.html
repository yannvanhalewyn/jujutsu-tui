jjtui

A fast, keyboard-driven terminal UI for navigating jujutsu repos — vim bindings, mnemonic single-key actions and marks for batch operations, modeled on the jujutsu.nvim plugin.

babashka ≥ 1.12.215 (JLine bundled) jj charm.clj (Elm architecture) EDN config

Install

git clone <repo-url> jujutsu-tui && cd jujutsu-tui
ln -s $(pwd)/bin/jjtui ~/bin/jjtui

Run (inside a jj or git repo)

jjtui [-r REVSET] [--config PATH]

In a git repo without jj, jjtui opens a chooser: i runs jj git init --colocate in the git repo's root (not the directory you started in), p opens the jj repo it sits inside, if any, and 1–9 open recently visited repos.

Develop

bb start [args]       # run jjtui from the checkout (same args as jjtui)
bb test               # run the test suite (includes jj integration tests)
bb seed               # list demo repo recipes
bb seed <recipe> [dir] # build a throwaway demo repo, default /tmp/jjtui-<recipe>

Each recipe also creates a bare origin next to the repo (e.g. /tmp/jjtui-basic-origin.git) and pushes main, so it's immutable. Recipes live in dev/jjtui/seed.clj, built with the helpers in dev/jjtui/repo_seed.clj.

bb seed basic: feature/login (2 changes), feature/docs and a WIP change — a good playground for every key below.

bb seed conflict builds a small Clojure project where feature/discounts (2 changes) was rebased onto a pushed main that rewrote the same function, so both changes are conflicted in src/shop/cart.clj; @ is an empty change on top of the first one, ready for resolving.

bb seed megamerge builds a small Clojure project in the megamerge workflow: feature/tags (2 changes) stacked on refactor/store, docs/usage and two unbookmarked dev changes, all off a pushed main, merged with jj new feature/tags docs/usage <dev tip> into a megamerge change; @ is an empty change on top of it.

Layout at a glance

  • Log pane — jj's own colored graph log (jj log with your templates.log, default revset or -r). The cursor is a highlighted change block; the gutter shows ● for marked changes.
  • Inline file lists under each change (status letter M/A/D/R/C + path), via tab for one change or shift+tab / i for all. File rows are selectable.
  • Split diff pane on the right (log | diff) that follows the cursor, rendered by a configurable preview command.
  • Status bar — mode, mark count, --ignore-immutable flag, revset, active diff tool, last message.
  • Bottom panel for menus, pickers and prompts; ? shows a full help overlay. d floats a small describe popup over the log instead.
  • External / interactive commands (diff tools, $EDITOR via jj describe --editor, jj split, jj squash that may open an editor) suspend the TUI, run in the real terminal, then the TUI resumes and refreshes.

Configuration

config.edn

File: $XDG_CONFIG_HOME/jjtui/config.edn, usually ~/.config/jjtui/config.edn (override with $JJTUI_CONFIG or --config). EDN, with the #env "VAR" reader supported. All keys are optional; your map is deep-merged over the defaults.

External diff tools

      
Used by enter and D; switch the active one at runtime with v. A string runs with sh -c (pipes ok, every substituted value shell-quoted). A vector is argv; a "$files" element expands to zero or more args. A map {:cmd … :wait? true} wraps either form and waits for a key after the tool exits (for tools that print and exit).

      
Besides :jj and :difftool, jjtui adds a preset for each of these programs it finds on PATH at startup. Defining the same key in :diff-tools replaces the preset.

Template variables

      
VariableExpands to

        
$from-shacommit id of the first parent of the oldest change in the selection; for D the fork point commit. With marks it is resolved via jj and needs a single root and head (otherwise jjtui reports an error).

        
$to-shacommit id of the newest change in the selection; for D the bookmark's commit

        
$revsetjj revset of the selection: the cursor change, the marked commit ids joined with  | , or fork_point(base | B)..B for D (base defaults to trunk())

        
$filesselected file paths, repo-relative; empty for the whole change

        
$widthpane / terminal width

        
$repoworkspace root

      

      
Commands run with the workspace root as cwd. If an interactive command exits non-zero (or the tool sets :wait? true), jjtui shows "Press any key to return to jjtui" before resuming. Tools using $from-sha / $to-sha (like difftool) require a colocated git repo.

    


    
    

      
Internals

      
Architecture

      
Built on charm.clj (Elm architecture: init / update / view).

      


      
Suspend / resume loop

      
Interactive commands need the real terminal. Instead of fighting the TUI for it, the program simply exits and is restarted with its saved state (pattern borrowed from prstack's run-in-fg).

      

        
      


      
App modes

      
jjtui.app is a pure update function over a small state machine:

      
:normal:pick:picker:menu:confirm:input:help:no-repo


      
Log parsing

      
jjtui keeps jj's own graph rendering. The log template prepends hidden markers to each change's node line — \x1d + \x1f-separated fields + \x1e — and appends \x1c-marked file lines for expanded changes (self.contained_in(<expanded revset>)), so jj still draws the graph and jjtui.log only has to strip and parse the markers.
